## 用户需求

在「搜索」页输入收藏夹名称时，搜索结果中应出现该收藏夹内的表情包。

## 产品概述

表情包管家（Vue 3 + Capacitor Android App）的搜索页当前仅支持按表情包上的文字/标签/情感搜索。用户希望扩展为：输入收藏夹名称时，能直接搜到该收藏夹里的表情。

## 核心功能

- 关键词命中收藏夹名称时，结果区上方展示匹配的收藏夹入口（封面缩略图、名称、表情张数），点击跳转收藏夹详情页 `/collection/:id`
- 匹配收藏夹内的表情合并进下方表情网格，与文字/标签搜索结果按 `id` 去重，统一过滤 `deleted_at = 0`（软删除表情不出现）
- 搜索框 placeholder 与初始空状态文案更新，提示支持按收藏夹名称搜索
- 搜索历史点击、防抖输入等既有交互自动复用新逻辑，无额外改动

## 边界与取舍

- 不改 `emojiRepo.search()` 的既有 SQL 逻辑；收藏夹匹配在前端 `runSearch()` 编排层合并，避免 JOIN 回归风险
- 不改数据库 schema（`collections`/`collection_items` 表已存在）、不改原生代码、不加新依赖
- 同一表情同时在多个命中收藏夹或命中文字时按 `id` 去重；空收藏夹仍展示入口但贡献 0 个表情；结果总量设上限（约 240）防止无限增长
- 验证方式：`npm run build` 类型检查 + Web 端 Mock 数据自测；无原生/schema 变更，不涉及真机回归

## 技术栈

- 前端：Vue 3 + TypeScript + Vite（既有栈，无新增）
- 数据层：既有 `@capacitor-community/sqlite` 仓库模式（参数化查询，Web 端 jeep-sqlite 兜底）
- 路由：既有 Vue Router（`/collection/:id` 已存在）

## 实现方案

在既有仓库层追加两个只读查询函数，在 `Search.vue` 编排层合并结果，UI 复用 `Collections.vue` 已有的收藏夹行样式。关键决策：

1. **复用 `toRecord`**：`emoji.ts` 的 `toRecord`（142 行）当前为模块私有，导出供收藏夹仓库复用，避免 `collection.ts` 再手写一份 row→EmojiRecord 映射（该文件 `getCollectionItems` 已有重复映射的前科）。导出本身零行为变化。
2. **SQL 全部参数化**：`searchCollectionsByName` 用 `name LIKE ?`；`getEmojisInCollections` 用 `IN (?,?,...)` 占位符拼接，遵循项目「参数化查询 + 手写转义才用 esc()」约定；查询统一带 `e.deleted_at = 0`，符合 CODEBUDDY.md §5 红线。
3. **编排层合并而非 SQL 联合查询**：`emojiRepo.search` 保持稳定，收藏夹匹配作为增量步骤追加，回归面最小。

## 关键改动文件

- `src/db/repositories/emoji.ts`：`function toRecord` 改为 `export function toRecord`。
- `src/db/repositories/collection.ts` [MODIFY]：新增两个导出函数——
- `searchCollectionsByName(keyword: string, limit = 10): Promise<Collection[]>`：`SELECT * FROM collections WHERE name LIKE ? ORDER BY is_default DESC, created_at DESC LIMIT ?`
- `getEmojisInCollections(collectionIds: string[], limit = 120): Promise<EmojiRecord[]>`：`SELECT DISTINCT e.* FROM emojis e JOIN collection_items ci ON ci.emoji_id = e.id WHERE ci.collection_id IN (...) AND e.deleted_at = 0 ORDER BY e.updated_at DESC LIMIT ?`，内部调用 `emoji.ts` 导出的 `toRecord`
- `src/views/Search.vue` [MODIFY]：
- script：新增 `matchedCollections` ref 与 `collectionStats`（id→{count, coverThumb}）；`runSearch()` 在 `emojiRepo.search` 后追加收藏夹匹配、统计拉取、表情合并去重（`Set<id>`，总量上限约 240）；新增 `openCollection(id)` 跳转
- 模板：结果计数下方、「收藏夹」标题 + 匹配收藏夹行（封面用 `toImageSrc`、名称、`N 张表情`），仅 `matchedCollections.length > 0` 显示；placeholder 改为「搜索表情包上的文字或收藏夹名称」；初始空状态 description 补充「或收藏夹名称」

## 性能与可靠性

- 每次搜索新增 1 次收藏夹名查询 + N≤10 次统计查询 + 1 次合并表情查询；防抖 300ms 已有，千级数据量下 LIKE + 索引足够，无 N+1 遍历全表问题
- 合并去重在内存完成，复杂度 O(n)；上限截断防止结果无限膨胀
- 异常处理沿用现有 try/catch + `console.error('search failed', e)` 模式，收藏夹查询失败不阻塞文字结果（降级为仅文字结果）

- `npm run build`（vue-tsc 类型检查必须通过）
- Web 端 Mock 数据：输入收藏夹名验证入口区块、表情合并、去重、空收藏夹、点击跳转

在既有搜索页内新增「收藏夹匹配」结果区块，不改变整体页面架构。新增区块完全复用 Collections.vue 已验证的收藏夹行样式：封面缩略图（`toImageSrc`）+ 名称 + 「N 张表情」次级文案，点击行整体跳转 `/collection/:id`。视觉上置于「找到 N 个结果」计数下方、表情网格上方，用与搜索历史一致的「小标题 + 列表」分组节奏（12px 次级文字、卡片圆角阴影），保持与现有设计系统（bg-card / shadow-card / text-ink-muted）一致，不引入新颜色与新组件。匹配收藏夹行的 hover 反馈与现有列表一致（hover:text-primary）。
