## 用户需求

首页收藏夹快捷入口中，点击某个具体收藏夹的按钮，不再跳转到该收藏夹的二级详情界面，而是在首页直接按该收藏夹筛选，仅显示属于该收藏夹的表情。

## 产品概述

在首页收藏夹横向快捷栏内，将"点击 chip 跳转二级页"改为"点击 chip 在首页筛选"。当前选中的收藏夹以高亮样式标记；再次点击同一 chip 取消筛选；"全部"按钮在筛选状态下变为"显示全部"用于清除筛选回到首页全部。收藏夹管理列表页（/collections）改由底部导航"收藏夹"进入（底部已有该入口），二级收藏夹详情页保留但不由首页 chip 进入。

## 核心功能

- 点击收藏夹 chip：在首页筛选并显示该收藏夹内容，同时高亮当前选中项
- 再次点击已选中的 chip 或点击"显示全部"：取消筛选，回到首页全部表情
- 标题栏"共 X 张"随筛选状态变化（筛选时显示该收藏夹数量）
- 删除/扫描/重新识别等刷新操作在筛选态下仍按当前筛选集合正确重载
- 多选、长按、分享、文件夹管理等首页其他行为不受影响

## 技术栈

- 沿用现有前端栈：Vue 3 + TypeScript + Vite + Pinia + Tailwind CSS
- 数据层：SQLite（`@capacitor-community/sqlite`），复用 `collectionRepo.getCollectionItems` 分页查询

## 实现方案

### 总体策略

在 `emojiStore` 中新增"首页收藏夹筛选"状态 `filterCollectionId`，统一由 `loadGrid` 根据是否有筛选决定取数来源：无筛选时走原有 `emojiRepo.getRecent`（全部、排除已删除），有筛选时走 `collectionRepo.getCollectionItems(id, …)`（已 JOIN collection_items 并过滤 `deleted_at = 0`）。前端 chip 点击改为切换该状态而非路由跳转，并据此渲染高亮与"全部/显示全部"文案。`Home.vue` 与 `emojiStore` 之间只通过新增的状态与动作通信，不引入新架构。

### 关键技术决策

- **取数切换放在 store 而非组件**：保持 Home.vue 仅负责展示与事件，数据来源、分页、计数逻辑集中在 `emojiStore`，与原 `loadGrid`/`refreshCounts` 一致，避免组件膨胀、便于删除/扫描后复用同一刷新入口。
- **复用 `getCollectionItems` 而非新建 SQL**：该函数已正确过滤软删表情并支持 `LIMIT/OFFSET` 分页，与原首页一致，零新增 SQL、无 FTS5 兼容风险，符合现有"读查询必须过滤 deleted_at=0"约定。
- **`total` 计数随筛选切换**：`refreshCounts` 在筛选态时读取该收藏夹数量（`collectionRepo.getCollectionStats(id).count`），否则 `countAll()`；`pendingCount`（全局待识别）保持原逻辑不随筛选变化。这样标题栏"共 X 张"在筛选时准确反映该收藏夹数量。
- **切换/取消筛选用单一动作 `setCollectionFilter(id|null)`**：传入已选中的 id 即清除（置 null），传入新 id 即切换；内部统一执行 `loadGrid(true)` 重置分页并 `refreshCounts` 刷新计数，避免多处重复逻辑。

### 性能与可靠性

- 取数与分页复杂度均为 O(PAGE)（索引走 collection_items 主键/JOIN），与原首页一致，无额外开销；`getCollectionItems` 已带 `deleted_at = 0`。
- 筛选态下的 `loadGrid(true)`/`refreshCounts` 与现有删除、扫描、重新识别后的刷新调用路径完全一致（均 reset 重新加载），不存在分页错乱或残留旧数据问题。
- 边界：筛选某收藏夹后若其中表情被软删/彻底删除，刷新后从数据源重新读取，数量与网格自动同步；筛选集合为空时由 `EmojiGrid`/`EmptyState` 现有分支兜底展示。

## 实现要点

- `emojiStore` 新增 `filterCollectionId`（`ref<string|null>`），导出 `setCollectionFilter`；`loadGrid` 与 `refreshCounts` 分支判断；从 `../db/repositories/collection` 引入 `getCollectionItems` 与 `getCollectionStats`。
- `Home.vue`：chip `@click` 改为 `onToggleCollection(col.id)`（调用 `emojiStore.setCollectionFilter`，再次点击同 id 则传 null）；chip 加 `:class` 高亮（选中时 `text-primary`/边框）；section 头部"全部"按钮在 `emojiStore.filterCollectionId` 非空时文案改为"显示全部"并改调 `setCollectionFilter(null)`，否则保持原有跳转收藏夹管理列表页入口（由底部导航承载，此处不再跳转）；标题栏 `emojiStore.total` 已自动反映筛选数量，无需改动。
- 不改动 `CollectionDetail.vue`、路由表、底部导航与 `openCollection` 函数（后者保留供收藏夹详情入口复用，但首页 chip 不再调用）。

## 架构设计

仅增强现有 Pinia 状态层与首页视图，数据流保持单向：
芯片点击 → `emojiStore.setCollectionFilter(id|null)` → 更新 `filterCollectionId` → `loadGrid(true)`/`refreshCounts` 切换数据源 → `items`/`total` 响应式更新 → `Home.vue` 网格与标题栏重渲染。

// src/stores/emoji.ts 新增签名（示意）
const filterCollectionId = ref<string | null>(null)

/** 切换首页收藏夹筛选；传入已选中 id 即清除（回到全部） */
async function setCollectionFilter(id: string | null): Promise<void> {
  filterCollectionId.value = id
  await loadGrid(true)
  await refreshCounts()
}
