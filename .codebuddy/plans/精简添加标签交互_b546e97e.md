## 用户需求

用户原话：「添加标签需要输入，添加，保存，步数太多了，精简一点」。

**现状问题**（已核实代码）：在 `src/views/EmojiDetail.vue` 添加一个标签需要 4 步——点「修正」进入编辑模式 → 输入文字 → 点「添加」（只改本地态，未写库）→ 点「保存」才持久化。中间任何一步离开页面都会丢失修改。

**精简目标**：

- 去掉「修正 / 保存」模式切换，标签区常开可编辑
- 输入后点「添加」或按回车 = 立即写库成功，无需再点保存
- 点标签 chip 上的 X 删除 = 立即生效
- OCR 文字修正改为失焦自动保存，并保留「保存成功 / 失败」的轻量反馈
- 不改动 store、repository、数据库结构（现有 `updateTags` / `updateUserTags` 已支持 `tags`、`ocrText` 单独部分更新）

**预期效果**：添加一个标签 = 输入 + 一次点击（或回车）；删除标签 = 点一次 X。全程无模式切换，任何操作即时落库，不再担心丢失修改。

## 技术栈

- 前端：Vue 3 + TypeScript + Vite + Pinia + Tailwind CSS（沿用现有栈，零新增依赖）
- 数据层：`@capacitor-community/sqlite`，经 `src/stores/emoji.ts` 的 `updateTags(id, data)` → `src/db/repositories/emoji.ts` 的 `updateUserTags`（已支持仅传 `tags` 或仅传 `ocrText` 的部分更新，动态拼 SET 语句），**无需改动**
- 影响面（ blast radius ）：仅 `src/components/TagEditor.vue` 与 `src/views/EmojiDetail.vue` 两个文件，store / repo / 原生层 / 其他页面零改动

## 实现方案

**核心思路**：把「本地暂存 → 显式保存」改为「每次变更即时持久化」。TagEditor 内部状态立即变（保持现有 v-model 契约与即时反馈），同时通过新增事件把「需要落库的动作」上报父组件，由父组件调 store 写库。

1. **`src/components/TagEditor.vue`**

- 新增两个 emit：`saveTags(tags: string[])`（增/删标签后触发）与 `saveText(text: string)`（OCR 输入框失焦时触发）；保留现有 `update:modelValue` v-model 契约与 `addTag` 的 trim、去重、空值过滤逻辑不变
- `addTag`：emit `update:modelValue` 后，用新数组同步 emit `saveTags`；回车添加（已有 `@keyup.enter`）保留
- `removeTag`：emit `update:modelValue` 后同步 emit `saveTags`（过滤后的数组）
- `updateText` 不变；textarea 增加 `@blur` → emit `saveText`
- 底部说明文案微调为「修改后自动保存」

2. **`src/views/EmojiDetail.vue`**

- 删除 `editing` ref、`onEdit`、`onSaveTags`，以及「修正 / 保存」按钮和只读展示块（215-234 行）；标签卡片常开 ``
- 新增 `onPersistTags(tags)` / `onPersistText(text)`：`try/catch` 包裹 `emojiStore.updateTags(item.id, { tags })` / `{ ocrText }`，成功后同步 `item.tags` / `item.ocrText` 并 toast「已保存」，失败 toast「保存失败，请重试」（复用现有 toast 机制）
- 清理不再使用的 `Pencil`、`Check` 图标 import

3. **异常与边界**：写库失败有 toast 兜底且不改变本地显示之外的状态；连续快速添加会触发多次单行 UPDATE（主键更新，毫秒级，无性能问题，无需合并批量）；OCR 失焦即存，避免离开页面丢失
4. **文档同步**：按项目约定（CODEBUDDY.md §8），更新 §4.2「标签修正」一行的流程描述为「常开编辑 + 即时保存」

## 性能与可靠性说明

- 每次增删标签 = 一条单行 `UPDATE emojis SET tags=?, updated_at=? WHERE id=?`，主键定位，开销可忽略；无 N+1、无重复遍历
- 不引入防抖：单次操作一次写库，语义最简单可靠；OCR 失焦才写，避免每敲一字一次 IO
- 向后兼容：`updateTags`/`updateUserTags` 签名与行为不变，其他调用方（如有）不受影响
