## 用户需求

将已放入 `src/assets/font/LeeeafHei-Regular.ttf`（3.85MB）的字体用作全站「标题字体」。

## 产品概述

在不改变正文系统字体的前提下，为应用内所有标题（页面主标题、区块标题、弹层/空状态标题等）统一套用新字体，提升标题的视觉辨识度与品牌气质。

## 核心功能

- 注册新字体并在 Tailwind 暴露 `font-title` 工具类（按需手动加 class，不做全局 h 标签覆盖）。
- 全站所有 h1/h2/h3 及页面主标题、区块标题、弹层标题、空状态标题统一加 `font-title`。
- 正文、按钮、底部 Tab 标签等保持原有系统字体不变。

## 技术栈

- 前端框架：Vue 3 + TypeScript + Vite
- 样式方案：Tailwind CSS（全局样式入口 `src/style.css`）+ `tailwind.config.js` 主题扩展
- 构建：Vite 资源处理（`url()` 引用会被打包进 assets，Web 与 Capacitor Android 均生效）

## 实现方案

### 总体策略

采用「CSS `@font-face` 注册 + Tailwind 字体族扩展 + 手动加 `font-title` 类」的三段式接入，完全复用现有样式体系（与 `font-sans` 并列，互不干扰），不引入新的构建插件或全局覆盖规则。

### 关键技术决策

1. **`@font-face` 放在 `src/style.css` 顶部（在 `@tailwind` 指令之前或 `@layer base` 内均可，`@font-face` 不受 layer 影响）**：使用相对路径 `url('./assets/font/LeeeafHei-Regular.ttf')`，由 Vite 解析为带 hash 的资源；`font-display: swap` 保证 3.85MB 字体下载期间先用 fallback 显示，不阻塞首屏。
2. **Tailwind 扩展 `fontFamily.title`**：key 为 `title`，工具类即 `font-title`；fallback 链保留 `'PingFang SC','Noto Sans SC',sans-serif`，避免字体未就绪时标题塌陷。fontFamily 与已有的 `sans` 平级，仅标题使用。
3. **按需手动加 class（非全局覆盖）**：严格按用户选择，不写 `h1,h2,h3{font-family}` 全局规则，逐个标题元素加 `font-title`，可控且便于后续微调。

### 性能与可靠性

- 单一字体文件 3.85MB，仅标题使用、`font-display: swap` 不阻塞渲染；Capacitor 打包后随 assets 进入 APK，无需联网。
- 不改动 `font-sans`，正文零影响；不新增全局样式，避免样式污染与回归。
- 风险点：相对路径必须相对 `src/style.css` 写 `./assets/font/...`；若写错路径会导致构建失败或 404，需在 `npm run dev` 后确认网络面板中字体 200 加载。

## 实现说明

- 仅修改样式与模板 class，不触碰任何业务逻辑、store、数据库与原生代码。
- 落地时按「标题语义」判断范围：页面 `<header>` 内 h1、各区块 `text-*-font-semibold` 小标题、弹层/空状态标题均纳入；正文段落、按钮、底部 Tab 标签（11px）不纳入。
- 注意：实际工程不存在 `Onboarding.vue`（CODEBUDDY.md 描述已过时），无需处理；以 `src/views/` 现有 8 个文件为准。
