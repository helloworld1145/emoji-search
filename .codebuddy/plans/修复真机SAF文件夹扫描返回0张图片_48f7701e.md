## 用户需求

真机安装 debug 包后，手动选择表情包文件夹（SAF 授权），首页表情网格完全空白，扫描到 0 张图片，无法识别。Web（Mock）调试模式正常，因此问题锁定在原生 SAF 扫描链路。用户希望先定位根因再修复，并保留真机可复现的验证手段。

## 产品概述

本任务为 Android 端「手动选文件夹扫描」功能的缺陷修复，目标是让真机在 Android 11+ 上正确枚举普通自建目录（含子目录）下的图片，使网格能显示缩略图、AI 识别标签、并能一键预览/分享原图。Web Mock 行为保持不变。

## 核心修复点

- 定位并修复原生 `FolderScannerUtil.scanTree` 对 SAF treeUri 枚举返回空（root 非目录 / `listFiles()` 返回 null / 权限未生效）的根因。
- 统一扫描返回的图片 `mtime` 单位（毫秒/秒）与缩略图缓存键，避免字段失真。
- 适配 `content://` 原图预览与分享链路（`toImageSrc` 与 `prepareForShare`），避免扫描修好后出现「有缩略图但大图/分享打不开」。
- 真机回归验证并更新 CODEBUDDY.md 已知坑点状态。

## 技术栈

- 保持现有栈：Android（Java）+ Capacitor 6（Android 包装）+ Vue 3 + TypeScript + Pinia + Tailwind CSS + SQLite。
- 不引入新依赖，仅在现有原生工具类与桥接/工具层内修复，沿用 `USE_MOCK` 双模式门面。

## 实现方案

### 1. 诊断先行（定位根因）

当前 `FolderScannerUtil.scanTree` 在异常时仅 `Log.e` 后返回空列表，`EmojiScannerPlugin.scanFolder` 在 `total=0` 时无任何日志，导致真机「静默失败」。首步在以下位置增加诊断日志后重新打包真机复现：

- `scanTree`：打印 root 是否非 null、`isDirectory()` 结果、`dir.listFiles()` 是否返回 null、递归各层的目录数与命中图片数、最终 `out.size()`。
- `scanFolder`：打印 `total`、`folderName`，并用 `getContentResolver().getPersistedUriPermissions()` 检查该 treeUri 是否真正持有持久读取权限。
据此区分三类根因：root 非目录、`listFiles()` 为空/null、权限未生效。

### 2. 修复 SAF 扫描枚举（核心）

依据诊断结果增强 `FolderScannerUtil`：

- `walk()` 中对 `dir.listFiles()` 返回 null 显式处理（真机高频根因：Android 11+ 部分 ROM/大目录/权限边界下 `DocumentFile.listFiles()` 返回 null）。
- 作为更可靠的兜底，改用 `ContentResolver` + `DocumentsContract.buildChildDocumentsUriUsingTree(treeUri, docId)` 显式查询子文档（列：`document_id`、`mime_type`、`_display_name`、`last_modified`、`size`），递归遍历子树；仅在显式查询也失败时才回退 `DocumentFile`。
- 保留现有扩展名图片过滤（`.png/.jpg/.jpeg/.gif/.webp/.bmp`）与目录跳过规则（`.` 开头 / `Android` / `LOST.DIR`）。
- 维持 `scanFolder` 的单线程 executor + 分页（limit 默认 300）逻辑不变，避免大目录一次性加载造成内存峰值。

### 3. 修复 mtime / 缩略图键一致性

`FolderScannerUtil.walk` 当前把 `f.lastModified()`（毫秒）作为 `ImageEntry` 第 6 参数（语义名为 `mtimeSec`）。`scanFolder` 用 `e.mtimeSec/1000L` 当秒传给 `ThumbnailUtil`（恰好正确），但回传给前端的 `o.put("mtime", e.mtimeSec)` 是毫秒，前端 `normalizeScanItem` 又判断 `<1e11` 再乘 1000 → 字段失真。统一为毫秒语义（重命名或换算一致），保证缩略图键与回传 `mtime` 一致，避免缓存命中异常与前端时间显示错误。

### 4. 适配 content:// 原图预览与分享（连带修复）

扫描修好后，网格缩略图走 `ThumbnailUtil` 生成的 `file://` 缓存（已可用），但：

- 大图预览（`EmojiDetail` 用 `path` 即 `content://`）经 `toImageSrc` 走 `Capacitor.convertFileSrc` 无效 → 新增原生桥 `getViewableUrl(path)`：对 `content://` 用 `ContentResolver` 拷贝到应用缓存返回 `file://`，对 `file://` 原样返回；`toImageSrc` 对 `content://` 改调此方法。
- `prepareForShare` 当前用 `new File(path)`，对 `content://` 会 `FILE_NOT_FOUND` → 改为 `ContentResolver` 拷贝（与 `getViewableUrl` 复用同一拷贝工具）。
- Web Mock 模式：`getViewableUrl` 返回原 `thumbUri`/路径，保持 Mock 行为不变。

## 实现注意事项

- 诊断日志定位后降级为 `Log.d` 或移除，不打印完整 URI 路径以避免隐私泄露与日志性能开销。
- 原图/缩略图拷贝均走 `cacheDir`，复用已有 `clear()` 清理，避免磁盘膨胀。
- 新增原生方法必须在 `nativeBridge.ts` 与 `mockScanner.ts` 同步提供 Mock 实现，保证 Web 调试不崩溃。
- 不改动 `scanner.ts` 的循环分页与入库编排、数据库表结构，仅修复数据来源与显示/分享桥接。

## 架构设计

仅改动现有原生工具类与前端桥接/工具层，不新增架构模式。数据流：
用户选文件夹 → `openFolderPicker` 持久化 treeUri → `scanFolder` 经修复后的 `FolderScannerUtil` 枚举 `content://` 图片 → `ThumbnailUtil` 生成 `file://` 缩略图缓存 → 前端入库 → 网格显示；详情/分享经 `getViewableUrl`/`prepareForShare` 将 `content://` 拷贝为 `file://` 加载或分享。

## 关键代码契约（前后端对接点）

`getViewableUrl` 新增原生方法契约（TypeScript 侧）：

- 入参：`{ path: string }`（`content://` 或 `file://` 路径）
- 返回：`{ url: string }`（`file://` 可加载 URL；`file://` 原样返回，`content://` 经缓存拷贝后返回）
- 异常兜底：拷贝失败时回退返回原 `path`，避免前端破图崩溃。
